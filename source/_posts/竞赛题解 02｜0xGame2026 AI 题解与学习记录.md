# Week 1

## 01｜粗心的小x

### 题目

> 新生小x刚学AI知识，用ChatGPT自己做了个和AI对话的小项目，可是gpt却告诉他不要泄露自己的APIKEY……小x不解：这是啥玩意？为啥会泄露捏？
>
> 忘说了，小x自学了git来管理项目，但是他好像不太懂怎么用…

附件有两个：`AI-chat-project.zip` 是聊天项目源码，带有 `.env` 配置和 `.git` 历史记录；`chat_export.json` 是小 x 与 AI 的聊天记录。

### 解题

**1.** `chat_export.json` 存在泄露的 key，去掉 `sk-` 后 Base64 解码，去掉前面的乱码得到：

```text
part1:0xGame{D0_n0t_
```

**2.** `git log` 查看 Git 历史记录，注意到：

```text
commit 79edd41829317bc5119fc1edd4632e4c90055327
    refactor: load model config from config.json
```

这次提交改了配置加载方式，看看 `chat.py` 删了什么：

```bash
git --no-pager show 79edd418 -- chat.py
```

发现三行删除，其中一行：

```python
client = OpenAI(api_key="sk-m2PzcGFydDI6dXBsT0BkX3ByMXY0dDM")
```

![Git 历史中被删除的 key](images/blog14/05-deleted-key.png)

泄露的 key 同样去掉 `sk-` 后 Base64 解码，得到：

```text
part2:uplO@d_pr1v4t3
```

**3.** `.env` 文件中存在新旧 API Key，分别 Base64 解码得到：

```text
part3:_th1ngs_t0_g1t}
This_is_a_fake_key
```

拼接得到：

```text
0xGame{D0_n0t_uplO@d_pr1v4t3_th1ngs_t0_g1t}
```


### Git 命令补充

*柯林对 Git 的终端指令不太熟悉，顺便补充一点*

这题 Git 历史不长，直接一眼盯真：

```bash
git --no-pager log -p -- chat.py
```

`-p` 展示每次提交的改动，`-` 开头的是删除行。

在包含 `.git` 的项目目录执行：

```bash
# 简洁查看提交历史，一行一个提交
git log --oneline

# 看某次提交改了哪些文件、增删了多少行
git show 79edd418 --stat

# 看这次提交完成后的完整文件
git show 79edd418:chat.py

# 看它的上一个版本中的文件
git show 79edd418~1:chat.py

# 列出某次提交保存的全部文件路径
git ls-tree -r --name-only 79edd418
```

`79edd418` 是提交 ID 的缩写，至少要有 4 位，并且能唯一匹配；`~1` 表示沿第一父提交往前一步。看差异时，`-` 是删除，`+` 是新增。输出停在 `(END)` 就按 `q` 退出，或者像前面一样加 `--no-pager`。

key 从代码里删了，Git 历史里还留着。`.gitignore` 也不会清掉已经提交的记录。怪不得每次把 key 放到对话里AI都会发出尖锐爆鸣声hh。

## 02｜ez_pytorch

### 题目

> 你从 Hugging Face 上下载了一个模型权重文件(.pth)。
> 这里有个加载脚本，但为啥报错了？

附件 `attach.zip` 中有 `load.py` 和 `model.pth`，分别是加载脚本和模型文件。

### 解题

**1.** 查看 `load.py`，加载模型的这一行：

```python
model = torch.load("model.pth", weights_only=True)
```

运行后报错：

```text
WeightsUnpickler error: Unsupported global: GLOBAL exec was not an allowed global by default.
```

简单解法是把这一行改为：

```python
model = torch.load("model.pth", weights_only=False)
```

改完重新运行就能输出 flag。不过我们可以深入一点，康康文件内部的逻辑。

**2.** 这份 `model.pth` 实际是 ZIP 压缩包，复制一份改后缀为 `.zip`，解压后找到 `data.pkl`。

*顺便一提，现在常见的 `.docx`、`.xlsx` 和 `.pptx`，普通未加密时也是 ZIP 容器，很神奇叭。*

在 `data.pkl` 所在目录用 Python 自带的 `pickletools` 查看指令：

```bat
python -m pickletools data.pkl > data_view.txt
```

打开 `data_view.txt`，找到 `GLOBAL '__builtin__ exec'`，后面的 `BINUNICODE` 存着一大段 Python 代码：

![data.pkl 的指令和代码字符串](images/blog14/06-pickle-disassembly.png)

这里可以用 [CyberChef 的 Unescape string](https://gchq.github.io/CyberChef/#recipe=Unescape_string()) 把 `\n` 还原成换行，方便阅读。

**3.** 代码已经写好了还原步骤，读取 `model/data/0` 到 `model/data/3`，分别处理：

- `data/0`：每个字节与 `0x5A`、`0xA3`、`0x3C` 循环异或。
- `data/1`：先用 `[::-1]` 反转字符串，再 Base64 解码。
- `data/2`：先将十六进制文本转成字节，每个字节减去自己的下标，再 `& 0xFF` 保留低 8 位。
- `data/3`：先 Base64 解码，首字节与 `0xA5` 异或，后面的字节分别与前一个输入字节异或。

四部分最终拼起来：

```python
_flag = (_p0 + _p1 + _p2 + _p3).decode()
```

把提取的 Python 代码保存为 `solve.py`，最后加上 `print(_flag)`，和原来的 `model.pth` 放在同一目录，执行：

```bat
python solve.py
```

得到：

```text
0xGame{3z_p1ckl3_fOr_pyt0rch}
```

### Pickle 反序列化

补充一点相关知识点叭，序列化是把对象转成字节保存，反序列化则将其恢复。Pickle 可以记录用于重建对象的函数和参数，`__reduce__` 在序列化时可以提供这份说明。

这道题的指令连起来看就是：

```text
GLOBAL      找到 exec 函数
BINUNICODE  取出代码字符串
TUPLE1      把字符串装进参数元组
REDUCE      用准备好的参数调用前面的函数
```

所以加载文件也可能运行其中的代码。`weights_only=True` 限制了可使用的函数和类型，遇到 `exec` 就报错，这也是题目的提示。原理可看 [Python 文档](https://docs.python.org/3/library/pickle.html#object.__reduce__) 和 [PyTorch 文档](https://docs.pytorch.org/docs/2.14/notes/serialization.html#torch-load-with-weights-only-true)。
